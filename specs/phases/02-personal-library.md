# Phase 2 — 个人照片库

**状态：** planned  
**依赖：** Phase 1

## 目标

主人本人，以及持有其有效 API Key 的 Agent，可以向个人库上传、列出、查看、修改元数据并删除照片。原图进入 S3 兼容对象存储，元数据进入 PostgreSQL。

## 范围内

- 上传原图：写入对象存储并插入 `photos` 行，初始状态 `processing`
- 列出与查看仅限该主人的照片，响应带元数据与可用的对象访问信息（签名 URL 或等价方式，实现时选定并写进本阶段说明）
- 修改描述、标签、拍摄时间、地点等可覆盖字段
- 删除照片时同时处理元数据与对象（策略在实现时写明：立即删除或标记后清理）
- 他人的 JWT 或 Key 不能读写这批照片
- 对象存储配置只来自环境变量（`S3_*`）
- 上传中断后续传：若本阶段做不到完整分片，必须在本文件写明留到哪一阶段，不得静默丢掉设计要求

## 范围外

- EXIF 解析、缩略图、视觉模型、向量（Phase 3）
- 搜索接口的召回语义（Phase 4）；本阶段列表只按主人与时间等直接过滤
- 共享册（Phase 5）
- 网页瀑布流（Phase 6）；本阶段以 API 与测试为准

## 领域触点

`domain/library`：照片实体、个人库访问规则、元数据覆盖规则、仓储端口。  
`gateways/storage`：对象存储端口的实现。  
身份上下文只提供主体，不在本阶段改写登录规则。

## 验收

- [ ] 主人用 JWT 或自己的 API Key 都能上传并在列表中看到该照片
- [ ] 其他用户不能读取或删除该照片
- [ ] 元数据修改只作用于调用者有权的照片
- [ ] 对象键与数据库行一致；存储凭证不出现在日志或响应正文
- [ ] 未配置真实对象存储时，测试可以使用本地假实现，且假实现位于网关层
- [ ] 领域层边界检查仍然通过
