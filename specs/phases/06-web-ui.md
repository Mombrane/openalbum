# Phase 6 — 网页

**状态：** planned  
**依赖：** Phase 1；各页面依赖其背后的 API 阶段（见验收）  
**设计：** [`docs/superpowers/specs/2026-11-06-openalbum-phase6-web-ui-design.md`](../../docs/superpowers/specs/2026-11-06-openalbum-phase6-web-ui-design.md)

## 目标

用 React（Vite）把已经可用的 API 做成人类能完成主路径的网页：注册登录、个人库、上传与详情、搜索、共享册、API Key。界面同时照顾桌面与手机宽度。

## 范围内

- 注册与登录
- 个人库瀑布流、上传、详情、元数据编辑、删除
- 关键词与自然语言搜索（API 来自 Phase 4）
- 创建与管理共享册、口令与成员角色；凭链接和口令进入
- 创建与吊销 API Key；明文只在创建成功时显示一次
- 加载、空列表、错误与未登录状态
- 与设计稿第 9 节 MVP 验收对应的一条端到端主路径（仅手工脚本，不引入 Playwright 或浏览器测试框架，并记录结果）

## 范围外

- 原生 App
- 新的后端能力；缺 API 时回到对应阶段 Spec，不在网页里堆隐藏接口
- 视觉品牌大改、国际化副本、管理后台

## 领域触点

网页不承载领域规则。它只调用已有 HTTP API。权限错误按 401 / 403 展示，不在前端再发明一套角色判断来替代服务端。

## 验收

- [ ] 用户能注册、登录、上传，并看到缩略图（依赖 Phase 3 的处理结果；处理中要有可见状态）
- [ ] 用户能用自然语言在个人库搜到照片
- [ ] 用户能创建 API Key，并用该 Key 在 API 上完成上传、改元数据与搜索（网页负责发 Key，API 行为由 Phase 1–4 保证）
- [ ] 用户能创建带链接和口令的共享册；另一账户能按角色上传或只读浏览
- [ ] 桌面与窄屏下主路径可用：登录、列表、上传、详情、搜索、共享册
- [ ] Phase 0 的占位文案被实际界面替换

## 依赖

Phase 1 为 `done` 才能做登录与 Key 页面。照片页面依赖 Phase 2，处理中状态依赖 Phase 3，搜索页依赖 Phase 4，共享册页面依赖 Phase 5。
