# Phase 5 — 共享册

**状态：** planned  
**依赖：** Phase 2；与 Phase 3、4 独立的部分可以并行，但册内展示若依赖缩略图与检索，需等对应阶段 `done` 后再接通。册的创建、口令与角色可以在照片原图可用之后实现。

## 目标

用户能创建活动或主题共享册，得到链接和口令。角色分为册主、可上传、只读。册主可以把册设为过期，或锁成只读纪念册。另一位用户或 Agent 凭链接和口令换取短期会话，并按角色上传或浏览。

## 范围内

- 创建、查看、修改共享册；口令只存哈希
- 成员与角色：`owner | uploader | reader`
- 口令兑换短期会话；口令与会话令牌不写入普通日志
- 按角色向册内添加已有照片或上传新照片（新照片仍进入上传者个人库，并出现在册中；若产品决定例外，必须改本文件后再实现）
- 过期与只读锁
- 无权限返回 403，响应不透露册是否存在
- 表与 `deploy/db/schema.sql` 中的 `albums`、`album_members`、`album_photos` 对齐

## 范围外

- 社交动态流、评论、点赞
- 开放 Agent 市场
- 完整网页视觉（Phase 6）；本阶段交付 API 与测试

## 领域触点

`domain/album`：册、角色、口令校验、过期与只读规则、仓储端口。  
上传仍走照片库与对象存储。身份上下文负责主体；册会话如果是另一种凭证，在身份或共享册中二选一并在本文件写明，避免两套互相看不见的主体。

## 验收

- [ ] 册主可创建册并设置口令；库内无口令明文
- [ ] 正确口令可以进入；错误口令被拒绝且不泄露册是否存在
- [ ] 只读角色不能上传；可上传角色不能修改册设置；册主可以
- [ ] 过期或只读锁按规则生效
- [ ] Agent 使用主人的 API Key 时，权限与主人在该册中的角色一致，没有额外后门
- [ ] 领域层边界检查仍然通过
