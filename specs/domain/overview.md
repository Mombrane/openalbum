# 领域概览

后端按四个限界上下文组织。依赖只能向内：接口层 → 适配层 → 领域层；DAO 与网关实现领域端口，领域层不引用 HTTP、SQL、对象存储或外部 SDK。

## 上下文

| 上下文 | 代码位置（Phase 0 仅占位） | 职责 | 引入阶段 |
|--------|------------------------------|------|----------|
| 身份 Identity | `apps/api/src/domain/identity` | 用户、口令凭证、会话、API Key 的生命周期与校验 | Phase 1 |
| 照片库 Library | `apps/api/src/domain/library` | 个人照片、元数据、处理状态；异步任务服务于照片生命周期 | Phase 2–3 |
| 检索 Search | `apps/api/src/domain/search` | 关键词与向量召回。读模型，不负责照片写入 | Phase 4 |
| 共享册 Album | `apps/api/src/domain/album` | 册、口令、成员角色、册与照片的关联 | Phase 5 |

## 关系

- 照片库、检索、共享册的写操作都要先分辨主体：人类会话或该用户的有效 API Key，规则归身份上下文。
- 检索读取照片库已经落库的描述、标签与向量，不另建一套照片事实。
- 共享册引用照片，不复制原图。权限按册角色判断；无权限时对外表现为拒绝，不泄露册是否存在。
- 处理流水线（EXIF、缩略图、视觉描述、嵌入）是照片状态机的一部分，落在照片库上下文；外部模型调用走网关，SQL 走 DAO。

## 端口（后续阶段在领域层定义，本阶段不建类型）

- 仓储：用户、API Key、照片、嵌入、共享册、任务
- 出站：对象存储、视觉描述、向量嵌入、时钟、ID

组合根是 `apps/api/src/index.ts` 与 `apps/api/src/app.ts`。它们可以装配各层；业务规则仍写在领域层。
