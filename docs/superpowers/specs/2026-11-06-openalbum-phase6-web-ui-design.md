## 1. 背景与目标

Phase 0 在 `apps/web` 留下 Vite、React 与 TypeScript 占位页。占位文案说明业务界面要到 Phase 6 才替换。API 已经能注册登录、签发 Access JWT 与 Refresh Token、管理 API Key，并完成个人库的分片上传、列表、详情、修改、删除和失败重试。Phase 4 的检索合同已经合并，实现尚未 `done`。Phase 5 只有阶段规格，没有 HTTP 合同。

本阶段把这些能力做成人类能走完的网页。网页不承载领域规则，不新增后端路由，不在浏览器里判断「这张照片是不是别人的」来替代 404，也不在浏览器里判断共享册角色来替代 403。权限以服务端响应为准。

交付物是 `apps/web` 里的中文界面，以及第 12 节手工脚本的执行记录。不改 `apps/api`。

界面文案只使用简体中文。`index.html` 的 `lang` 保持 `zh-CN`。

## 2. 已定决策一览

| 议题 | 决定 |
|------|------|
| 路由 | History API，路径在站点根上。不使用 hash 路由，不引入路由库。路径表见第 4 节 |
| 窄屏与桌面 | 断点 `40rem`。小于它使用底部导航，大于等于它使用顶部导航。主路径在 375 与 1280 宽度都要能走完 |
| 会话存放 | Access JWT 与 Refresh Token 只放在页面内存。不写入 `localStorage`、`sessionStorage`、`IndexedDB`、Cookie 或 URL。整页刷新后必须重新登录 |

| 网页凭证 | 浏览器只使用密码会话的 Access JWT。不把 API Key 或 Refresh Token 当作网页的 Bearer |
| 上传 | 单文件、单片。创建会话、`PUT` 第 1 片、完成。会话 id 只留在当次页面内存。没有会话列表接口，刷新页面不能续传。`completing` 与「上传未能完成」只重试完成，不新开会话 |
| 处理中 | 列表和详情展示 `processing` / `ready` / `failed` 的文字。`processing` 时每 5 秒 `GET` 一次。没有任务查询路由，网页不发明 |
| 搜索 | 页面按 Phase 4 合同调用 `POST /photos/search`。`searchCallsEnabled` 默认 `false`。Phase 4 未 `done` 时不发检索请求，也不用 `GET /photos` 在浏览器里过滤来冒充搜索 |
| API Key | 明文 `secret` 只在创建成功的当次视图里出现一次。离开该视图即从内存丢掉。列表只显示 `keyPrefix` 等非秘密字段 |

| 错误展示 | 只展示第 7 节允许列表里的 `message`。其它响应使用按状态码固定的中文。不把响应插进 HTML |
| 同源 | 浏览器只请求同源的 `/api/...`。生产靠现有 Nginx 反代，本地靠 Vite 代理。不给 API 增加 CORS，不读取 `PUBLIC_BASE_URL`、`CORS_ORIGIN`、`S3_PUBLIC_BASE_URL` |
| 验收 | 第 12 节手工脚本。不引入 Playwright 或网页测试依赖。`npm test` 仍只跑 API |
| 明确不做 | 原生 App、新后端能力、品牌大改、国际化、管理后台、Cookie 会话、记住我 |

## 4. 路由与信息架构

路由由 `history.pushState` 与 `popstate` 驱动。服务端和 Vite 都把未知路径回落到 `index.html`，这是现有 Nginx `try_files` 与 Vite 的默认行为。本阶段不改 `deploy/nginx.example.conf`。

路径按下面的顺序匹配，先匹配先生效。

| 路径 | 未登录 | 已登录时的页面 |
|------|--------|----------------|
| `/login` | 登录 | 替换为 `/` |
| `/register` | 注册 | 替换为 `/` |
| `/upload` | 去 `/login` | 上传 |
| `/search` | 去 `/login` | 搜索 |
| `/keys` | 去 `/login` | API Key |
| `/account` | 去 `/login` | 账户：邮箱、到 API Key 的链接、退出 |
| `/albums/new` | 去 `/login` | 创建共享册 |
| `/albums/:id` | 去 `/login` | 共享册详情。`:id` 必须是第 8 节的 UUID，否则「页面不存在」 |
| `/albums` | 去 `/login` | 共享册列表 |
| `/photos/:id` | 去 `/login` | 照片详情。`:id` 同样必须是 UUID |
| `/join/:slug` | 口令进入。不要求已登录 | 同一页，外壳使用已登录导航 |
| `/` | 去 `/login` | 个人库 |
| 其它 | 「页面不存在」 | 「页面不存在」 |

`:slug` 是恰好一段路径，不含 `/`，不是空，不是 `.` 或 `..`，UTF-8 字节长度 1 到 200。口令不放在路径、查询或哈希里。

未登录访问受保护路径时，把该路径记在内存变量 `returnTo`。只接受上表里的站内路径，长度不超过 200，以单个 `/` 开头，不含 `//`、`\` 和 `://`。`/login` 与 `/register` 不记。登录或注册成功后，若 `returnTo` 仍符合这条规则，就去那里并清空；否则去 `/`。不把 `returnTo` 放进查询字符串。

已登录外壳：

- 视口宽度大于等于 `40rem`：顶部导航，链接为「照片」「搜索」「上传」「共享册」「API Key」，另有当前邮箱和「退出」。没有底部导航。
- 视口宽度小于 `40rem`：底部导航五项，「照片」「搜索」「上传」「共享册」「账户」。邮箱和退出放在 `/account`。顶部只留产品名，链到 `/`。

产品名固定为「AI Native 共享相册」，链到 `/`。当前路径对应的导航项用 `aria-current="page"`。

未登录的登录页和注册页不渲染这套导航，只在两页之间放文字链接。口令页在未登录时只显示产品名和「登录」链接。

「页面不存在」提供回到「照片」或「登录」的链接，不请求 API。

## 5. 会话

Phase 1 不发 Cookie。网页不得改成 Cookie 会话，也不得为了「记住我」增加后端接口。

内存里只保存这些字段：`accessToken`、`accessTokenExpiresAt`（客户端 `Date.now()` 加上响应里的 `accessTokenExpiresIn` 秒）、`refreshToken`、`user.id`、`user.email`。不保存密码。不解码 JWT，不从 JWT 读取角色或邮箱。

注册成功（201）与登录成功（200）使用同一套写入。注册成功后不再调用登录。刷新成功（200）替换两枚令牌和过期时刻，并更新邮箱。

主动刷新：在 `accessTokenExpiresAt` 前 60 秒触发。若 `accessTokenExpiresIn` 小于等于 60，则改为在 TTL 的一半处触发，且不早于 1 秒之后。定时器全页一个。标签页隐藏时定时器继续跑，避免回到页面时成串 401。

单飞：模块级一个 Promise。定时器与 401 重试共用它。进行中的刷新不会发出第二次 `POST /auth/refresh`。Phase 1 规定并发的第二次刷新会吊销整个 family。

受保护请求返回 401 时：若这次请求还没有因为刷新重试过，就等待这一次刷新，然后用新的 Access JWT 重试原请求一次。刷新本身返回 401，或重试后仍是 401：清空内存，取消定时器，去 `/login`，页面显示「登录已失效」。不循环刷新。

`POST /auth/refresh` 不带 `Authorization`。请求体只有 `{ "refreshToken": "<当前明文>" }`。

退出调用 `POST /auth/logout`，请求体同样只有 `refreshToken`，不带 Bearer。204 或 401：清空内存并去 `/login`。网络失败或 500：保留内存会话，显示第 7 节的对应文案，用户仍处于登录态，可以再点退出。

整页刷新会丢掉内存。下次打开 `/` 必须看到登录页。实现不得把令牌写进任何持久存储来绕过这一点。开发者工具里的 `localStorage` 与 `sessionStorage` 不得出现 Access JWT、Refresh Token、`oalr_`、`oalb_` 或 API Key 明文。

登录、注册、刷新、退出、上传和创建 API Key 都由用户点击触发。不在渲染函数里发请求。React StrictMode 双调用效应时，列表、详情和 Key 列表的 `GET` 可以发生两次；刷新必须仍然只有一个在途请求。页面卸载时用 `AbortController` 取消该页的 `GET`。不要取消模块级的刷新。

## 6. 页面与状态

各页区分五种视图状态：`loading`、`empty`、`ready`、`error`、以及表单自己的 `submitting`。第一次请求返回前不得把空列表当成「还没有照片」。请求进行中，触发它的按钮不可再次点击。

照片对象网页只读取这些键：`id`、`contentType`、`byteSize`、`takenAt`、`locationText`、`latitude`、`longitude`、`description`、`tags`、`status`、`errorCode`、`originalUrl`、`originalUrlExpiresAt`、`thumbUrl`、`thumbUrlExpiresAt`、`createdAt`、`updatedAt`。搜索结果额外读取 `score`。其它键忽略，不展示。`originalUrl` 与 `thumbUrl` 只放进 `img` 的 `src`，不作为可见文字，不写进前端日志。

`errorCode` 的可见文案：

| `errorCode` | 文案 |
|-------------|------|
| `null` 且 `processing` | 处理中 |
| `storage`、`vision_unavailable`、`embed_unavailable` | 处理中，将自动重试 |
| `original_missing` | 原图缺失 |
| `thumbnail_failed` | 缩略图失败 |
| `vision_rejected` | 描述被拒绝 |
| `embed_rejected` | 嵌入被拒绝 |
| `dimension_mismatch` | 向量维度不符 |
| `invalid_embedding` | 向量无效 |
| 其它非空值 | 处理未完成 |

`failed` 使用同一张表，但可重试的三项在 `failed` 下改为「处理失败，可以重试」。`ready` 的可见状态是「已就绪」，不展示 `errorCode`。状态必须有文字，不能只靠颜色。

`img` 的替代文本：描述 trim 后非空则用描述，否则用「照片」。浏览器解不开 HEIC 或 RAW 时，保留元数据和状态文字，并显示「图片暂时无法显示」。不把解码失败当成删除失败。

签名 URL 在过期时刻前 60 秒，或图片 `error` 事件发生时，对该 id 再 `GET` 一次并替换地址。同一次展示最多因为 `error` 重取一次。第二次仍失败就留下「图片暂时无法显示」。

### 6.1 注册与登录

字段只有邮箱和密码。没有显示名、验证码或第三方登录。

邮箱在提交前 trim。本地用 Phase 1 的正则 `^[^\s@]+@[^\s@]+\.[^\s@]+$` 和长度 1–320 检查 trim 后的值。不在本地改大小写。不合法时显示「邮箱格式不正确」，不发请求。

密码按 JavaScript 字符串长度 8–128。不要求字符类别。不合法时显示「密码长度须为 8 到 128」，不发请求。密码框 `type="password"`。登录使用 `autocomplete="current-password"`，注册使用 `autocomplete="new-password"`。邮箱分别使用 `username` 与 `email`。

注册请求 `POST /auth/register`，正文 `{ "email", "password" }`。成功后写入会话并离开本页。409 且允许列表命中时显示「该邮箱已注册」，并给出登录链接。

登录请求 `POST /auth/login`。401 且 `error.code` 为 `invalid_credentials` 时显示「邮箱或密码错误」。不额外提示邮箱是否存在。

提交失败时焦点移到该页的错误摘要。错误摘要使用 `aria-live="polite"`。

### 6.2 个人库

进入 `/` 后请求 `GET /photos?limit=50`。没有其它查询参数。排序使用接口返回的顺序，网页不重排。

空数组且 `nextCursor` 为 `null`：显示「还没有照片」和到 `/upload` 的链接。

每张卡片是到 `/photos/:id` 的链接。卡片上有缩略图（`thumbUrl` 非空时）和状态文字。没有缩略图时用状态文字占位，不用裂图图标单独表达状态。`byteSize` 用二进制单位显示：大于等于 1048576 时除以 1048576 保留一位小数并加 ` MiB`，大于等于 1024 时除以 1024 四舍五入到整数并加 ` KiB`，否则显示字节数加「 字节」。时间显示 `createdAt` 的本地 `YYYY-MM-DD HH:mm`。

`nextCursor` 非空时显示「加载更多」。点击后用同一个 `limit=50` 和该游标请求下一页，把结果接在后面。加载中按钮不可点。`nextCursor` 为 `null` 时不显示按钮。不用无限滚动。

当前已加载的卡片里只要有 `processing`，就每 5 秒对每个这样的 id 调用一次 `GET /photos/:id`，用返回值替换该卡片。同时最多 4 个在途详情请求，多出来的排到下一轮。标签页隐藏时暂停这组轮询。状态不再是 `processing` 后，该 id 退出轮询。不轮询 `ready` 与 `failed`。不因为轮询把焦点移走。

### 6.3 上传

只接受一个文件。控件不是 `multiple`，不要求拖放。

本地类型：`file.type` 去掉参数、trim、转成小写后，若属于 Phase 2 第 6.1 节的白名单，就用它。否则按下表用扩展名（大小写不敏感）。两边都不中：显示「不支持的文件类型」，不发请求。不读文件头。

| 扩展名 | `contentType` |
|--------|----------------|
| `.jpg`、`.jpeg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |
| `.heic` | `image/heic` |
| `.heif` | `image/heif` |
| `.cr2` | `image/x-canon-cr2` |
| `.nef` | `image/x-nikon-nef` |
| `.arw` | `image/x-sony-arw` |
| `.dng` | `image/x-adobe-dng` |

`file.size` 不在 1 到 33554432 之间：显示「文件大小须为 1 字节到 32 MiB」，不发请求。

通过检查后按顺序：

1. `POST /photos/uploads`，JSON `{ "contentType", "byteSize": file.size }`。
2. `PUT /photos/uploads/:id/parts/1`，`Content-Type: application/octet-stream`，正文是整个文件的字节。`:id` 是响应里的 `upload.id`，不是 `photoId`。文件不超过 32 MiB，单片就是最后一片，允许小于 5 MiB。不把文件切成多片，也不在完成请求里提交 ETag。
3. `POST /photos/uploads/:id/complete`，JSON `{}`。

界面按步骤显示「正在创建上传」「正在上传」「正在完成」。不要求百分比。创建响应里的 `objectKey` 与分片响应里的 `etag` 不展示。

完成后 201 或 200，且正文有 `photo.id`：去 `/photos/` 加上这个 id。

失败时的按钮：

| 结果 | 界面 |
|------|------|
| 创建阶段网络失败或 500 | 「重新上传」。重新从创建会话开始 |
| 分片阶段网络失败或 500 `storage_error` | 「重试分片」。对同一 `upload.id` 再 `PUT` 第 1 片，然后完成 |
| 完成阶段 409 `upload_completing` | 显示「上传正在完成」。间隔 1 秒再调用完成，最多自动 3 次。用尽后保留「继续完成」，只调用完成 |
| 完成阶段 500 且文案「上传未能完成」 | 「继续完成」。不新建会话，不重传分片 |
| 409 `upload_closed`，或会话 404 | 「上传已结束」。丢掉会话 id，只能重新选择文件 |
| 用户在上传步骤点击「取消」且中止返回 204 | 回到空表单，显示「已取消上传」 |
| 中止返回 409 `upload_completing` | 转入上面的完成重试。不声称已经取消 |
| 中止返回 409 `upload_completed` | 再调用一次完成；得到照片就进入详情 |

会话 id 与 `photoId` 只存在这次页面的内存里。刷新、关闭标签或退出后不恢复上传。没有 `GET` 会话的接口，网页不扫描对象存储。

`completing` 期间不提供取消。中止请求的正文是 `{}`。

### 6.4 详情与元数据

进入页面先 `GET /photos/:id`。404 显示「未找到」，不解释这张照片是否属于别人。

`processing` 时用第 6.2 节的 5 秒间隔轮询这一张。隐藏标签页时暂停。

页面包含原图（`originalUrl`）、状态、内容类型、字节大小、创建时间，以及可编辑字段：描述、标签、拍摄时间、地点、纬度、经度。描述使用多行文本，最长 4000。地点最长 500。标签是逐个添加的芯片，不是逗号分隔的语法。添加前 trim，空串丢掉，控制字符（U+0000–U+001F 与 U+007F）拒绝并显示「标签不合法」，重复项保留第一次，最多 32 个，每一项 1–64。拍摄时间用 `datetime-local`，提交时用 `new Date` 转成 `toISOString()`。无法解析则显示「拍摄时间不合法」，不发请求。清空拍摄时间则提交 `null`。纬度与经度必须同时为空或同时为有限数字。只填一个时显示「经纬度须成对出现」，不发请求。超出闭区间纬度 −90 到 90、经度 −180 到 180 时显示「经纬度超出范围」，不发请求。两个都空则提交两个 `null`。

保存发送 `PATCH /photos/:id`。正文只包含这六个键：`description`、`tags`、`takenAt`、`locationText`、`latitude`、`longitude`。描述 trim 后为空则 `description` 为 `null`，地点同样。不发送 `status`、`errorCode`、`contentType`、`byteSize`、`id`。成功后用响应替换页面。描述或标签与打开页面时的值不同，且响应仍是 `ready`：额外显示「已保存。描述或标签变更后会重新嵌入，状态保持已就绪。」不为此轮询，因为没有任务查询接口，状态也不会因此变成 `processing`。只改时间或地点时显示「已保存」。

删除先打开页内对话框，文案「删除这张照片？此操作不能撤销。」确认后 `DELETE /photos/:id`。204 则去 `/`。对话框打开时焦点进入对话框，Tab 循环在对话框内，Escape 等于取消，关闭后焦点回到「删除」。

仅当 `status` 为 `failed` 时显示「重试」。点击发送 `POST /photos/:id/retry`，正文 `{}`。200 后用响应替换页面并恢复轮询。409 `not_failed` 显示「照片不在失败状态」，不插入本地假状态。`processing` 与 `ready` 不显示「重试」。

### 6.5 搜索

表单有模式、查询，以及可留空的开始时间、结束时间和标签。模式是单选：「关键词」或「自然语言」。控件默认选中「关键词」，请求里的 `mode` 仍写所选字符串，取值为 `keyword` 或 `semantic`。

关键词的说明固定为「匹配描述或标签里的连续文字，不分词。」自然语言的说明固定为「在已就绪的照片里按语义查找。」页上另有一句「只检索已就绪的照片。」

`searchCallsEnabled` 为 `false` 时，提交显示「检索接口尚未就绪」，不发请求。

为 `true` 时，提交 `POST /photos/search`，没有查询字符串。正文规则：

- `mode` 为所选值。
- `q` 为 trim 后的查询。长度为 0：显示「查询为空」，不发请求。UTF-16 码元大于 500：显示「查询过长」，不发请求。
- 没有标签时省略 `tags`。有标签时用与详情相同的芯片规则，放进 `tags`。
- 时间省略的一端不放进 JSON。有值时用 `toISOString()`。两端都有且开始晚于结束：显示「时间范围不合法」，不发请求。
- 不发送 `status`、`offset`、`topK`、`albumId` 或其它 Phase 4 未列出的键。
- `limit` 为 20。

结果使用与个人库相同的卡片。`mode` 为 `semantic` 时，卡片显示「相关度 」以及响应 JSON 里的 `score`。可见数字与该 JSON 数字一致，不二次舍入。格式化不得改变数值语义：不用 `toFixed`，也不另做四舍五入、截断或乘除。JSON 数字 `1` 就显示为 `1`。`score` 为 `null` 时不显示相关度。

空数组显示「没有匹配的照片」。这是 200，不是错误。

「加载更多」把上一页的 `nextCursor` 放进 JSON 的 `cursor`，并带上当前表单的 `mode`、`q` 和过滤器。不把游标放进 URL。用户改变模式、查询或过滤器后再次提交，则丢掉游标，从第一页重新来。

503 且允许列表命中时显示「嵌入暂不可用」。502 命中时显示「嵌入被拒绝」。不展示向量、上游正文或查询以外的调试信息。查询本身留在输入框里。

搜索结果不展示 `processing` 或 `failed`。接口不会返回它们。网页不得把个人库列表滤一遍当作搜索结果。

### 6.6 API Key

进入 `/keys` 后 `GET /api-keys`。空数组显示「还没有 API Key」。

列表按接口顺序展示 `name`、`keyPrefix`、`createdAt`、`lastUsedAt`。`lastUsedAt` 为 `null` 时显示「从未使用」。`revokedAt` 非空时显示「已吊销」，且不显示「吊销」按钮。未吊销的行有「吊销」，点击后 `DELETE /api-keys/:id`。204 后重新 `GET` 列表。不显示 `secret`，也不拼接一个假的完整 Key。

创建字段只有名称。trim 后长度 1–64，且不含控制字符。否则显示「名称不合法」，不发请求。成功 201：在页内对话框显示 `secret` 一次，放在只读文本框里，并有「复制」。复制使用 `navigator.clipboard.writeText`。剪贴板失败时文本框仍可选中，显示「复制失败，请手动选择」。对话框说明固定为「关闭后无法再次查看。」关闭、按 Escape、或导航离开本页时，从内存删除 `secret`。不把 `secret` 放进 `history` 状态、URL、`document.title` 或日志。再次打开列表不得还看得到它。

网页自身的请求始终使用 Access JWT。即使用户刚复制了 Key，后续的 `fetch` 也不改用这枚 Key。用 Key 调用上传、修改和搜索是第 12 节里的 curl，不是浏览器会话。

403 显示「当前凭证不能执行该操作」。正常的密码会话走不到这条。

### 6.7 账户

`/account` 显示当前邮箱、到 `/keys` 的链接和「退出」。退出行为见第 5 节。

### 6.8 共享册

本节只定信息架构和状态机。HTTP 路径、JSON 字段、口令如何兑换、成员如何写入，全部以将来的 Phase 5 设计为准。本文件不给出 `/albums` 的请求形状，实现在 `albumCallsEnabled` 变为 `true` 之前也不得创建这样的请求。

`albumCallsEnabled` 为 `false` 时：

- `/albums` 显示横幅「共享册接口尚未接通。」和「还没有共享册」，以及到 `/albums/new` 的链接。
- `/albums/new` 渲染下面的表单。提交不发请求，显示同一条横幅，并清空口令框。
- `/albums/:id` 显示横幅和标题「共享册」。不显示假册名、假成员或假照片。
- `/join/:slug` 显示路径中的 slug 文本、口令框和「进入」。提交不发请求，显示同一条横幅，并清空口令框。不显示册标题。

创建表单的字段：标题、说明、口令、再输入一次口令、可清空的过期时间。接通前的本地校验只有：标题 trim 后至少 1 个码元；两遍口令相同，且 trim 后至少 1 个码元。不满足时分别显示「请填写标题」「两次口令不一致」，不发请求。不在本文件规定标题上限、口令字符集或过期时间的 JSON 形状。接通时，本地校验改成 Phase 5 设计已经写明的规则；那里没写的规则不保留。口令框 `type="password"`，不写入 URL 和持久存储。

详情页按服务端返回的角色渲染。角色只接受 `owner`、`uploader`、`reader`，可见名称依次为「册主」「可上传」「只读」。未知角色显示「当前凭证不能执行该操作」，不猜测一个本地角色。网页不设置默认角色。

控件是信息架构的上限。Phase 5 设计写了对应写操作才绑定请求；没写的控件不渲染。

| 控件 | 册主 | 可上传 | 只读 |
|------|------|--------|------|
| 修改标题、说明、口令、过期、只读锁 | 渲染 | 不渲染 | 不渲染 |
| 修改成员角色 | 渲染 | 不渲染 | 不渲染 |
| 从个人库添加已有照片 | 渲染 | 渲染 | 不渲染 |
| 上传新照片并加入此册 | 渲染 | 渲染 | 不渲染 |
| 浏览册内照片 | 渲染 | 渲染 | 渲染 |

个人库选择器使用已经存在的 `GET /photos`。确认加入册的那一下属于共享册写操作，常量未打开时不发请求。上传新照片再加入册时，字节仍走第 6.3 节的个人库上传；「加入此册」是其后的共享册写操作。加入失败时照片留在个人库，显示「照片已进入个人库，加入共享册失败」，并加上第 7 节允许的服务端文案。不自动删除这张照片。常量未打开时，册详情上的上传控件不开始个人库上传，避免用户以为照片已经进册。

册内照片只渲染共享册响应里自带的展示字段。若其中包含与个人库相同的 `thumbUrl` 和 `status`，状态文字沿用第 6 节。没有这些字段时，只显示 Phase 5 设计允许展示的文本。不拼接对象键，不用 `GET /photos/:id` 去补册内照片。别人的照片用个人库接口会得到 404，网页不用这个 404 区分「没有」和「不是你的」。

过期或只读锁以服务端字段为准。字段表示已过期或已锁定时，可上传角色不再渲染添加和上传。册主仍渲染设置控件。网页不用本地时钟把一本册判成过期。常量未打开时不显示「已过期」或「只读纪念册」。

口令进入成功后，去这本册的详情。失败时，只要 HTTP 状态是 401、403 或 404，都显示「无法进入」。不显示「册不存在」「口令错误」或册标题。Phase 5 若规定了另一句固定 `message`，接通后改展示那句，且那句必须放进第 7 节的允许列表；仍然不得根据不同状态码改成两种泄露存在性的句子。

册主复制的链接是同源的 `/join/` 加上服务端返回的 slug。网页不把口令附在链接上。

成员区在没有成员数据时显示「还没有其他成员」。不放示例成员。

## 7. 加载、空、错误与权限

网络在收到 HTTP 状态之前失败：显示「网络不可用，请重试」，并提供重试按钮。该按钮只重复刚刚失败的那一次 `GET`，或重复上传状态机里已经定义的分片或完成。不自动重试注册、登录、创建 Key、删除照片和退出。

响应不是 JSON，或没有 `error.code` 与 `error.message`：按状态码使用下面的兜底句，不展示原始正文。

| 状态 | 兜底句 |
|------|--------|
| 400 | 请求不合法 |
| 401 | 未授权 |
| 403 | 当前凭证不能执行该操作 |
| 404 | 未找到 |
| 409 | 请求冲突 |
| 413 | 文件超过 32 MiB |
| 500 | 服务器错误 |
| 502 | 嵌入被拒绝 |
| 503 | 嵌入暂不可用 |
| 其它 | 服务器错误 |

登录接口的 401 在 `error.code` 为 `invalid_credentials` 时用「邮箱或密码错误」，不用上表的「未授权」。会话被清空后的 401 用「登录已失效」。口令进入页的 401、403 与 404 不用上表，固定用第 6.8 节的「无法进入」。

只有 `message` 与下面的允许列表完全一致时，才展示服务端的 `message`。否则用兜底句。比较前不 trim 服务端文案。搜索路由另按本节后面的对照表选句，不因为同为 400 就先改成兜底句。

允许展示的 `message`：

- 请求不合法
- 邮箱格式不正确
- 密码长度须为 8 到 128
- 名称不合法
- 标识不合法
- 未授权
- 邮箱或密码错误
- 当前凭证不能执行该操作
- 该邮箱已注册
- 未找到
- 不支持的文件类型
- 文件大小须为 1 字节到 32 MiB
- 分片不合法
- 描述不合法
- 标签不合法
- 地点不合法
- 拍摄时间不合法
- 经纬度须成对出现
- 经纬度超出范围
- 上传已结束
- 上传正在完成
- 上传已完成
- 文件超过 32 MiB
- 对象存储不可用
- 上传未能完成
- 删除未能完成
- 修改未能完成
- 照片不在失败状态
- 查询为空
- 查询过长
- 时间范围不合法
- 嵌入被拒绝
- 嵌入暂不可用
- 服务器错误

`POST /photos/search` 的可见错误句以 Phase 4 设计第 8 节的固定中文为准，并且必须与上面的允许列表逐字相同，不另写一套措辞。该路由返回 400 且 `error.code` 为 `validation_error` 时，按响应里的 `message` 展示，不把这一状态码收成兜底句。Phase 4 规定的四句是「请求不合法」「标签不合法」「拍摄时间不合法」「时间范围不合法」。非法 `tags` 的固定句是「标签不合法」。非法 `takenFrom` 或 `takenTo` 的固定句是「拍摄时间不合法」。`takenFrom > takenTo` 的固定句是「时间范围不合法」。其余不合法正文才是「请求不合法」。`message` 与其中一句逐字相同就展示该句。不得因为 `code` 同为 `validation_error`，就把「标签不合法」或「拍摄时间不合法」改成「请求不合法」。

搜索相关的全部固定中文如下。每一句都已经在允许列表中：

| 状态 | `error.code` | 固定 `message` |
|------|----------------|----------------|
| 401 | `unauthorized` | 未授权 |
| 400 | `validation_error` | 请求不合法 |
| 400 | `empty_query` | 查询为空 |
| 400 | `query_too_long` | 查询过长 |
| 400 | `validation_error` | 标签不合法 |
| 400 | `validation_error` | 拍摄时间不合法 |
| 400 | `validation_error` | 时间范围不合法 |
| 502 | `embed_rejected` | 嵌入被拒绝 |
| 503 | `embed_unavailable` | 嵌入暂不可用 |
| 500 | `storage_error` | 对象存储不可用 |
| 500 | `internal_error` | 服务器错误 |

上表之外的搜索 `message` 仍用本节兜底句，不展示自由文本。比较前不 trim。

Phase 5 接通时，只把它的设计里已经写明的固定 `message` 追加进允许列表。不展示自由文本。

空状态文案：

| 场景 | 文案 |
|------|------|
| 个人库没有照片 | 还没有照片 |
| 搜索没有命中 | 没有匹配的照片 |
| 没有 API Key | 还没有 API Key |
| 没有共享册 | 还没有共享册 |
| 册内没有其他成员 | 还没有其他成员 |

加载中的文案是「正在加载」。它不是错误，也不是空状态。

前端可以按第 6 节不渲染当前角色用不到的按钮。按钮渲染出来之后，仍然以 HTTP 结果为准。服务端返回 403 或 404 时，即使按钮刚才可见，也按本节展示，不改写成另一套角色解释。不解析 JWT 来隐藏别人的照片。个人库接口只返回主人的照片，网页不再滤一遍 `owner`。

## 8. API 客户端

所有请求的路径都以 `/api` 开头。浏览器看到的是同源 URL。生产环境由已有 `deploy/nginx.example.conf` 把 `location /api/` 反代到 `127.0.0.1:3000` 并去掉前缀，因此 API 收到的路径没有 `/api`。本阶段不修改 Nginx、`deploy/env.example` 或 API。

本地实现必须改 `apps/web/vite.config.ts`：把以 `/api` 开头的请求代理到 `http://127.0.0.1:3000`，并去掉 `/api` 前缀。开发服务器端口保持 `43123`。不增加 `VITE_API_URL` 之类会把浏览器指向另一个源的变量。

API 进程不读取 `CORS_ORIGIN`、`PUBLIC_BASE_URL` 和 `S3_PUBLIC_BASE_URL`。网页不读取它们，不把它们打进前端包，也不要求给 API 加 CORS。照片字节由浏览器直接请求响应中的签名 URL。网页不改写签名 URL。

受保护请求的头是 `Authorization: Bearer <accessToken>`。`POST` JSON 使用 `Content-Type: application/json`。分片使用 `application/octet-stream`。不使用 `multipart/form-data`。

允许的调用只有：

| 方法 | 去掉 `/api` 前缀后的路径 | 批次 |
|------|--------------------------|------|
| `POST` | `/auth/register` | A |
| `POST` | `/auth/login` | A |
| `POST` | `/auth/refresh` | A |
| `POST` | `/auth/logout` | A |
| `POST` | `/api-keys` | A |
| `GET` | `/api-keys` | A |
| `DELETE` | `/api-keys/:id` | A |
| `POST` | `/photos/uploads` | A |
| `PUT` | `/photos/uploads/:id/parts/1` | A |
| `POST` | `/photos/uploads/:id/complete` | A |
| `POST` | `/photos/uploads/:id/abort` | A |
| `GET` | `/photos` | A |
| `GET` | `/photos/:id` | A |
| `PATCH` | `/photos/:id` | A |
| `DELETE` | `/photos/:id` | A |
| `POST` | `/photos/:id/retry` | A |
| `POST` | `/photos/search` | B，且常量已打开 |

不调用 `GET /me`。邮箱来自注册、登录或刷新响应里的 `user`。不调用 `GET /photos/search`。不调用 `GET /health`。不注册 `POST /photos/uploads/:id/parts/:partNumber` 的其它片号。

共享册在常量打开后，只允许 Phase 5 设计文件里出现过的方法与路径。那个文件没写的路径，客户端函数也不加。

UUID 使用 Phase 2 的正则，大小写不敏感，放进路径前转成小写。不匹配的照片 id 和册 id 不发请求，直接「页面不存在」。

`GET /photos` 的查询参数只有 `limit` 与可选的 `cursor`。`limit` 固定为十进制 `50`，不含前导零。

## 9. 响应式与无障碍

断点只有一个：`40rem`。小于该宽度是窄屏，大于等于是桌面。不建第二套站点，不按 User-Agent 分流。

窄屏：个人库一列；详情里图片在表单上面；底部导航每项最小高度 `2.75rem`。桌面：内容区最大宽度 `72rem` 并水平居中；个人库为 `repeat(auto-fill, minmax(11rem, 1fr))` 的等宽网格，缩略图 `aspect-ratio: 1`、`object-fit: cover`。这就是本阶段的瀑布流。不引入瀑布流库，不按原图比例做不规则排版。焦点顺序跟 DOM 一致。

375 与 1280 两种宽度下，登录、个人库、上传、详情、搜索和共享册都不得出现横向滚动条。主路径指这六处，加上 API Key 页。

无障碍底线：

- 每个输入都有可见的 `<label>`。
- 导航、提交、删除、重试、复制和关闭都是 `<button>` 或 `<a>`，名称来自可见文字。
- 第一个可聚焦元素是「跳到内容」，目标是该页的 `<main>`。
- 状态变化放在 `aria-live="polite"` 的区域里，包括「处理中」变为「已就绪」或失败文案。
- 对话框（删除确认、API Key 明文）在打开时把焦点移入，Tab 不离开对话框，Escape 关闭。
- 不把悬停当作唯一操作方式。
- 不自动播放，不加需要 `prefers-reduced-motion` 才能关掉的位移动画。本阶段没有动画。

沿用 `apps/web/src/index.css` 里已有的 `--bg`、`--ink`、`--muted`、`--line`、`--accent`、`--paper` 和字体族。可以改布局和间距。不更换主色，不加标志图，不加插画。正文在窄屏不小于 `16px`。链接和状态文字使用 `--ink` 或 `--muted`，不把 `--accent` 当成状态的唯一载体。

## 10. 安全展示

- 令牌、密码、API Key 明文、共享册口令不进入持久存储、URL、`document.title`、`history.state` 和 `console`。
- 服务端文案以 React 文本节点展示。不使用 `innerHTML` 或 `dangerouslySetInnerHTML`。
- 签名 URL 不出现在可见文字里。
- 创建会话返回的 `objectKey` 不出现在可见文字里。
- API Key 对话框关闭后，状态里不再持有 `secret`。
- 口令与密码不提供「复制」按钮。
- 登录失败不区分邮箱是否存在。共享册进入失败不区分册是否存在。
- 不在网页里实现验证码、限流或账户锁定。Phase 1 已经写明：在没有限流之前不要把注册和登录暴露到公网。这句话留在部署说明里，网页不新增门槛，也不删掉部署说明里的警告。

## 11. 模块边界

运行时依赖保持 `react` 与 `react-dom`。不新增路由库、组件库、状态库、国际化库或数据请求库。开发依赖不新增测试运行器。

文件划分固定如下。`src/pages/` 里的页面可以按路由再拆文件，但不得因此增加运行时依赖。

| 文件 | 职责 |
|------|------|
| `src/features.ts` | `searchCallsEnabled` 与 `albumCallsEnabled` |
| `src/session.ts` | 内存令牌、单飞刷新、定时器 |
| `src/api.ts` | `fetch`、`/api` 前缀、错误外壳、第 8 节的路径 |
| `src/router.tsx` | 第 4 节的路径表 |
| `src/copy.ts` | 固定中文与 `errorCode` 对照 |
| `src/shell.tsx` | 顶部或底部导航 |

`src/App.tsx` 的 Phase 0 占位在批次 A 移除。占位里的阶段名单、`Phase 0 · 脚手架` 和「尚未开始」不再渲染。

实现后 `npm run typecheck -w apps/web` 必须通过。根目录 `npm test` 的范围不变，仍然只检查分层并跑 API 测试。网页验收不靠这个命令。

## 12. 手工验收脚本

验收方式是手工脚本，不是浏览器自动化。现有 `apps/web` 没有测试运行器。主路径要人眼确认缩略图、窄屏和「明文只出现一次」。

每一批的实现说明都贴上执行记录：步骤编号、通过或失败、失败时的可见文案和 HTTP 状态。没有记录的批次不算通过。

共同前提：

- 按仓库已有方式启动 PostgreSQL、对象存储配置和 API。本地网页用 `npm run dev:web`。API 用 `npm run dev:api`。处理流水线用 `npm run worker -w apps/api`。
- `NODE_ENV` 不是 `production`，这样未配置真实嵌入时可以使用现有假嵌入。
- 浏览器打开 `http://127.0.0.1:43123`。再准备一个隐私窗口，作为第二个账户。
- 桌面宽度 1280。窄屏宽度 375。

### 12.1 批次 A

此时两个常量都是 `false`。

1. 未登录打开 `/`。看到登录页。页面正文没有 `Phase 0 · 脚手架`，也没有「尚未开始」。
2. 注册一个新邮箱。进入个人库，看到「还没有照片」。
3. 退出后用错误密码登录，看到「邮箱或密码错误」。再用正确密码登录，进入个人库。
4. 刷新浏览器。回到登录页。开发者工具里的 `localStorage`、`sessionStorage` 和控制台输出都没有 Access JWT、Refresh Token、`oalr_` 或 `oalb_`。
5. 重新登录。上传一张小于 32 MiB 的 JPEG。依次看到创建、上传、完成的步骤，并进入详情。在 worker 完成前看得到「处理中」。
6. 停留在详情。先确认看得到「处理中」。假视觉配置下，最终描述是「未配置视觉模型」。通过标准是状态变为「已就绪」，并且缩略图或原图可见。若变为失败文案，页面上必须有「重试」；这一结果记为失败，不拿来代替「已就绪」。
7. 把描述改为 `海边灯塔验收` 并保存。看到已保存的说明，状态仍是「已就绪」。这张照片留到批次 B，不删除。
8. 再上传一张小的 PNG，在详情里删除。对话框出现「删除这张照片？此操作不能撤销。」确认后回到个人库，PNG 不见，JPEG 还在。
9. 打开 API Key 页，创建名称 `验收 Agent`。对话框里的明文以 `oalb_` 开头。把它记在终端里，不要记进网页。关闭对话框后再进入此页，明文不再出现。列表有前缀，没有完整秘密。先不要吊销。
10. 用记下来的 Key 作为 Bearer，在终端依次调用 `POST /photos/uploads`、`PUT /photos/uploads/:id/parts/1`、`POST /photos/uploads/:id/complete` 和 `PATCH /photos/:photoId`。请求形状以 Phase 2 设计为准。完成响应里有照片，`PATCH` 为 200。这不是浏览器里的操作。完成后回到网页吊销这枚 Key，该行显示「已吊销」。
11. 在 1280 与 375 各走一遍登录、个人库、上传入口和一张照片的详情。375 下底部五项导航可见，这四个页面没有横向滚动条。1280 下是顶部导航，没有底部导航。
12. 打开搜索页并提交。看到「检索接口尚未就绪」。网络面板没有 `/api/photos/search`。
13. 打开共享册列表、创建页和任意一个形如 `/join/demo` 的口令页并提交。看到「共享册接口尚未接通」。网络面板没有路径中含 `album` 的请求。

第 10 步的 Key 在批次 A 已经被吊销，所以批次 B 若要测 Key 搜索，须再创建一枚，用完再吊销。

### 12.2 批次 B

Phase 4 已经 `done`，`searchCallsEnabled` 为 `true`，`albumCallsEnabled` 仍为 `false`。使用批次 A 留下的那张描述为 `海边灯塔验收` 的照片。它必须已经是 `ready`。

1. 关键词查询 `灯塔`。结果里有这张照片，没有相关度数字。
2. 关键词查询 `红 船`。这张照片不在结果里。空结果的文案是「没有匹配的照片」。
3. 查询框只输入空格后提交。看到「查询为空」。网络面板没有新的搜索请求。
4. 自然语言查询的文本与这张照片的嵌入文本一致。没有标签时，嵌入文本就是描述 `海边灯塔验收`。结果里有这张照片，相关度为 `1`。假嵌入保证同一段文本的分数为 `1`。不要改用另一句自然语言来要求分数为 `1`。这一步依赖 worker 写完重新嵌入，网页不为重新嵌入自动轮询。人工等待上限是 3 分钟：相关度还不是 `1` 时，每隔 5 秒在搜索页再提交一次。超过 3 分钟仍不是 `1`，这一步失败。
5. 再上传一张新照片，打开它的详情，确认状态是「处理中」并记下 `id`。用关键词 `灯塔` 搜索。结果里有第 1 步那张已就绪的照片，没有这个仍在处理中的 `id`。个人库里仍看得到「处理中」。
6. 新建一枚 API Key。用 curl 发送 `POST /photos/search`，分别用 `keyword` 与 `semantic`，`q` 使用第 1 步和第 4 步的文本。两次都返回这张照片的 id。然后在网页上吊销这枚 Key。
7. 在 1280 与 375 各提交一次关键词搜索。两种宽度都没有横向滚动条，结果可以点进详情。

### 12.3 批次 C

Phase 5 设计已合并且该阶段为 `done`，`albumCallsEnabled` 为 `true`。角色的准备步骤使用 Phase 5 设计里已经写明的操作。本段不另写 HTTP。若某条可见结果所依赖的写操作不在 Phase 5 设计里，这一条记为阻塞，不在网页里补接口。

1. 账户 A 创建共享册并设置口令。页面给出可复制的链接，路径以 `/join/` 开头。链接和页面 URL 里都没有口令。
2. 账户 B 打开该链接，输入错误口令。可见文案不包含「不存在」，也不出现册标题。
3. 账户 B 输入正确口令后进入册页。
4. 只读角色的册页没有「添加照片」「上传」和册设置。可上传角色看得到第 6.8 节表格里已经由 Phase 5 设计给出写操作的控件，其中必须有「从个人库添加已有照片」或「上传新照片并加入此册」至少一项，且没有册设置。册主看得到册设置，包括过期与只读锁。
5. 可上传角色上传或添加的照片出现在册内，并且仍出现在该用户的个人库。
6. 册主把册锁成只读，或设成已过期。可上传角色再看此页时，添加和上传不再出现。
7. 在 1280 与 375 各做一次创建和口令进入。两种宽度都没有横向滚动条。

## 14. 明确不做

本阶段不做：

- 原生 App、小程序，以及任何非 `apps/web` 的客户端
- 新的后端路由、字段、Cookie 会话、CORS 中间件或限流
- 修改 `apps/api`、`deploy/**`、`specs/SPEC.md` 的阶段状态（实现提交按第 3 节更新状态除外；本设计提交不更新）
- 视觉品牌更换、标志、插画、暗色模式、国际化文案
- 管理后台、用户管理、审计日志页面
- 社交动态、评论、点赞、人脸、地图、以图搜图
- 共享册内搜索
- 用浏览器过滤 `GET /photos` 来冒充 `POST /photos/search`
- 在 Phase 5 设计公布前调用或定义共享册 HTTP
- 记住我、把令牌放进 `localStorage` 或 `sessionStorage`
- 多文件队列、拖放、预签名直传、把一个文件切成多片
- 百分比上传进度、无限滚动、不规则瀑布流库
- 邮箱验证、找回密码、修改密码、验证码
- 服务工作者、离线包、安装提示
- 网页测试框架。验收只使用第 12 节

实现时禁止：

- 把 Refresh Token 放进 `Authorization`
- 并发发出两次 `POST /auth/refresh`
- 在界面或前端日志里展示令牌、口令、API Key 明文、签名 URL 和 `objectKey`
- 根据本地角色判断把 403 改写成「册不存在」或把 404 改写成「这是别人的照片」
- 为了接通共享册而在 `apps/api` 增加未写入 Phase 5 设计的路由

## 15. 已确认决策

- 网页是 Phase 0 脚手架上的 React 界面。运行时依赖只有 `react` 与 `react-dom`。路由用手写的 History API。
- 桌面用顶部导航，窄屏用底部导航，断点 `40rem`。瀑布流是等宽网格，不是不规则排版库。
- Access JWT 与 Refresh Token 只在内存中。刷新单飞，并在 401 时重试原请求一次。整页刷新后重新登录。网页不用 API Key 当自己的会话。
- 上传是单文件单片，能在同一次页面里重试分片或继续完成。没有会话列表，所以不能在刷新之后续传。
- 处理中的照片留在个人库里，用文字和 5 秒轮询可见。搜索只按 Phase 4 检索已就绪照片。
- API Key 明文只在创建成功的对话框里出现一次。
- 共享册的页面、角色和「无法进入」文案在本文件定稿。HTTP 以 Phase 5 设计为准，接通前不发请求。
- 浏览器只走同源 `/api`。不新增 CORS，不读取 `PUBLIC_BASE_URL`。
- 验收是第 12 节的三段手工脚本。Phase 4 与 Phase 5 未完成时，对应段落不假装通过。
